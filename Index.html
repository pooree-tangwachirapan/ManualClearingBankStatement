ภาพรวม

โปรแกรมนี้ทำอะไร

หลังรับ bank statement เข้าระบบแล้ว รายการเงินเข้า–ออกจะค้างอยู่ใน G/L บัญชีพักธนาคาร (บัญชีที่คุม open item) โปรแกรมนี้หาคู่ของรายการเหล่านั้นตามกติกาของแต่ละโหมด แล้วสร้างใบเคลียร์ให้ ผู้ใช้ไม่ต้องเลือกทีละบรรทัดใน FB05 เอง

Incoming

เงินเข้า · จัดกลุ่มแล้วเคลียร์
  • จัดกลุ่มรายการตามตัวเลือก Grouping 11 แบบ
  • กลุ่มที่ยอดรวมเป็น 0 ถูกเคลียร์ด้วยใบ IC
  • แก้ Text / Assignment / Ref Key3 ของใบเคลียร์ตามตัวเลือก

ดูวิธีใช้ Outgoing →

เริ่มใช้งาน

ใช้งานใน 6 ขั้น

  1. เข้า T-code ZCMXXE004เปิดหน้า Selection Criteria ค่าเริ่มต้นคือโหมด Incoming
  2. เลือกโหมดด้วยปุ่ม radioหน้าจอจะแสดงเฉพาะช่องของโหมดที่เลือก ช่องของโหมดอื่นถูกซ่อน
  3. กรอกเงื่อนไขช่องบังคับต่างกันในแต่ละโหมด (ดูในหัวข้อของโหมดนั้น) กด F4 ที่ Company Code, G/L Account, Business Area, Document Type, Customer เพื่อเลือกจากรายการ
  4. กด Execute F8หรือบันทึกเป็น Variant ไว้ใช้ซ้ำ / ตั้งเป็น background job
  5. ตรวจหน้าผลดูกลุ่มหรือคู่ที่โปรแกรมหามาให้ แถวแดงคือรายการที่จะไม่ถูก post
  6. กดปุ่ม post ของโหมดIncoming: Auto Choose · Outgoing: Execute · In+Out: Simulate แล้ว POST — จากนั้นดูเลขใบเคลียร์และข้อความในคอลัมน์ท้ายตาราง
ก่อนกดปุ่ม post

ทุกปุ่ม post สร้างเอกสารบัญชีจริงทันที หากเคลียร์ผิดคู่ ต้องให้ฝ่ายบัญชีกลับรายการเคลียร์ด้วย FBRA (Reset Cleared Items)

กด Auto Choose แล้วเกิดอะไร

  • post ทุกกลุ่มที่ช่อง Status ยังว่าง กลุ่มละ 1 ใบเคลียร์
  • ใบเคลียร์: ชนิด IC · Reference ZARP003 · สกุล THB · Posting Date = วันล่าสุดของใบ IB ในกลุ่ม
  • ไฟเขียว = สำเร็จ · เลขใบเคลียร์อยู่ในคอลัมน์ DocumentNo ช่องท้าย (ถัดจาก Amount — ชื่อซ้ำกับเลขเอกสารต้นทางแบบเดียวกับ ZARP003) · ไฟแดง = ดูข้อความในช่อง Message
  • กดซ้ำหลัง post แล้วจะได้ข้อความ No data posting ไม่มีการ post ซ้ำ

  • ผลลัพธ์ออกเป็น spool ของ job
  • แนะนำให้บันทึก Variant ที่ระบุ G/L และ Grouping ไว้ก่อนตั้ง job

โปรแกรมจับคู่อย่างไร

ใบ IB 1 ใบ จับกับใบรับเงิน (RC) ที่บริษัท, G/L และสกุลเงินเดียวกัน และ Posting Date ของ RC อยู่ในช่วง 5 วันย้อนหลังนับรวมวันของ IB · ลองตามลำดับ 3 ด่าน ใบที่จับได้แล้วจะไม่ถูกใช้ซ้ำ

ด่าน 11 IB : 1 RC ยอดเท่ากัน

IB 10,000.00=RC 10,000.00

ยอดตรงกันพอดี ไม่มีบรรทัดผลต่าง

ด่าน 21 IB : 1 RC ต่าง ≤ 1.00

IB 10,000.00≈RC 9,999.50

ผลต่าง 0.50 ลงบัญชีผลต่าง 41099099 Miscellaneous Income

ด่าน 31 IB : หลาย RC

IB 10,000.00≈RC 6,000.00RC 3,999.80

สะสมยอด RC จนต่างจาก IB ไม่เกิน 1.00

Grouping แบบ Text (ตัวเลือก 1, 2, 4, 5) รวมทุกใบที่ Text เหมือนกันเป็นกลุ่มเดียว แล้วดูแค่ว่ายอดรวมเป็น 0 ถ้าข้อมูลใช้ Text ซ้ำกันหลายใบ ใบใดก็ตามที่ยอดหักลบกันพอดีจะถูกจับคู่กัน โปรแกรมเดิมใน ECC ทำแบบเดียวกัน · ถ้าจะจับคู่ด้วยเลขอ้างอิงให้ใช้ตัวเลือกที่มี Assignment (3, 6, 10)

เคลียร์แล้ว ทำไมเลขเอกสารยังอยู่ในหน้าผล

เอกสารธนาคารมีหลายบรรทัด บรรทัดที่อยู่ในบัญชีธนาคารหลักซึ่งไม่คุม open item จะไม่มีวันถูกเคลียร์ จึงโผล่ทุกครั้งที่รัน (ECC ก็เป็นแบบนี้) · ใส่ G/L Account เฉพาะบัญชีพักที่คุม open item ในหน้าจอเลือกข้อมูล บรรทัดเหล่านั้นจะไม่ติดมา

เคลียร์ผิดคู่ไปแล้ว ทำอย่างไร

ให้ฝ่ายบัญชีกลับรายการเคลียร์ด้วย FBRA ด้วยเลขใบเคลียร์ (Incoming: คอลัมน์ DocumentNo ช่องท้าย · Outgoing: DocumentNo (IC)) รายการจะกลับมาค้างเหมือนเดิม แล้วรันโปรแกรมใหม่ด้วย Grouping ที่ถูกต้อง

ใบ DM หรือชนิดอื่นโผล่มาในโหมด Incoming ได้อย่างไร

ช่อง Document Type ถูกแก้ไม่ให้เหลือแค่ค่าเริ่มต้น D4 D5 D6 IB หรือถูกลบจนว่าง โปรแกรมจึงดึงทุกชนิดเอกสาร ตรวจช่องนี้ใน Variant ก่อนรัน
